# Runbook

For a local Docker deployment, copy `.env.example` to `.env`, review its synthetic credentials, and run `docker compose up --build -d`. The API/dashboard is exposed on loopback port 8080. `/healthz` checks database reachability and the WAL failure latch. Persistence uses separate PostgreSQL and WAL volumes. Preserve both stores together. Do not remove volumes to troubleshoot a queue failure.

Native dependencies: CMake 3.20+, C/C++20 compiler, POSIX sockets, iconv, PostgreSQL/libpq, OpenSSL, and GoogleTest (or network access for the pinned fallback). On macOS, provide `-DCMAKE_PREFIX_PATH='/opt/homebrew/opt/postgresql@17;/opt/homebrew/opt/openssl@3;/opt/homebrew/opt/googletest'` when configuring. Use an existing local PostgreSQL database and set `PULSE_DATABASE_URL`. The daemon defaults to loopback only. Source `set -a; source .env; set +a` in a shell before native execution.

`PULSE_OPERATOR_TOKEN` registers devices and reads metrics. `PULSE_CLINICS` is a JSON array of `clinic_id` and bearer `token` values. Startup inserts or updates these clinic credentials in the database. Omitting a previously registered clinic does not revoke it; this prototype has no credential lifecycle API. Device registrations are immutable and contain their schedule. Use a fresh synthetic device ID for a changed registration. Tokens are hashed using SHA-256; use long random bearer credentials in shared environments. The checked-in values are synthetic demonstration credentials. The service accepts plaintext HTTP on a private/local network; a shared deployment needs a separately configured TLS ingress.

`PULSE_HTTP_THREADS` defaults to 8 (1–128); `PULSE_WORKERS` defaults to 4 (1–32); `PULSE_QUEUE_ITEMS` defaults to 100000 (1–1000000). Queue options must remain unchanged for an existing directory, as required by the base queue. Configure `PULSE_BIND`, `PULSE_PORT`, and `PULSE_WAL_DIR` as needed. Do not run two daemons on one WAL directory. The native executable serves schema/dashboard assets from its configured source path; keep that directory available. The Docker image includes the assets at the compiled path.

If processing fails, inspect `pulse_retry_total` and `pulse_queue_pending`, restore database service, and let workers retry. Accepted events remain queued. If admission returns 503, clients retry the identical event with backoff. If `/healthz` reports a queue failure, stop the process and preserve the WAL for inspection before restarting. DDQ recovery validates records and handles an incomplete final tail. Do not manually delete segments or manifests. Corruption is an error requiring operator investigation.

Prometheus is optional: create `.secrets/prometheus-token` containing the operator token, readable by the Prometheus container user, then run `docker compose --profile monitoring up -d`. Its scrape endpoint is `telemetry:8080/metrics`; Prometheus UI binds to loopback 9090. The built-in dashboard also retrieves queue counters with an operator credential. Its clinic views use an independently supplied clinic credential, stored only in the page's input memory. There is no browser token persistence or third-party script dependency.

SIGINT/SIGTERM stops accepting sockets and joins workers. Pending work remains in DDQ. A production 30-second lease can delay recovery of a claimed event until lease expiration. Clock changes can affect this wall-clock lease, as in upstream DDQ. Test-only shorter leases and crash points require `PULSE_ENABLE_TEST_HOOKS=1`; never configure them for ordinary use.

Run `ctest --test-dir build --output-on-failure`. For real-database tests, set `PULSE_TEST_DATABASE_URL` to a disposable test database and run `python3 tests/integration.py` and `python3 tests/crash_matrix.py --rounds 100`. Set `PSQL` if the client is not on PATH. The harness creates a unique schema and temporary WAL directory, then removes only those owned artifacts. Use `PULSE_BINARY=build-asan/pulsestream` or a corresponding Release/TSan executable to select a build. Abruptly interrupting the harness itself may leave its uniquely named schema, which can be inspected before cleanup.

Capacity and retention are prototype limits: history views return 100 records, there is no pagination or schedule editing API, clinic-level review does not identify individual staff, audit/event history has no retention policy, and the system has one WAL owner. Readiness is not a medical monitoring guarantee. Use synthetic data only.

The optional browser smoke test is `python3 scripts/ui_smoke.py` with `PULSE_TEST_DATABASE_URL` set. It requires Node, the `playwright` package, and a compatible Chromium install. `PULSE_PLAYWRIGHT_MODULE` may point to an existing package directory; `PULSE_CHROMIUM_PATH` may select an existing browser binary. It verifies status, delivery/acknowledgment, metrics, clinic isolation, and a mobile viewport, and saves `docs/evidence/dashboard.png`.
